# v0.9 Findings, Registry, Indexing, and Dashboard Model

## 1. New operational chain

```text
Normalized Evidence
       |
       +--> Evidence Registry
       |
       v
Control Assessment
       |
       +--> PASS / REVIEW
       |
       +--> FAIL
              |
              v
           Finding
              |
       +------+------+
       |             |
 Remediation      Exception
       |             |
       +------+------+
              v
            Retest
```

## 2. Separate indices

The framework recommends:

```text
pdp-evidence-*
pdp-assessment-*
pdp-findings-*
```

This separates technical evidence, assessment state, and remediation workflow.

## 3. Finding boundary

A finding states:

```text
Control PDP-ACC-003 failed for this assessed scope.
```

It does not state:

```text
The organization violated Article 39.
```

The latter requires legal assessment.

## 4. Evidence Registry

The registry stores metadata about evidence location and lifecycle.

It allows:

```text
assessment -> evidence ID -> registry -> indexed document/source
```

without embedding raw telemetry everywhere.

## 5. Dashboard objective

The dashboard is an engineering/compliance-operations view.

Primary questions:

- Which controls are failing?
- Which controls need review?
- Which evidence sources are degraded?
- Which processing activities have open findings?
- What evidence quality is available?
- Which technical events are recurring?
- Which controls trace to which legal requirements?

## 6. Index mapping policy

Mappings are explicit and strict.

This reduces accidental field-type drift and prevents arbitrary payload fields from silently expanding index mappings.

## 7. Retention

Suggested starting point only:

```text
evidence      365 days
assessments   2+ years
findings      retain through closure + audit period
```

Actual retention must be defined by organizational/legal requirements rather than hard-coded as PDP law.

## 8. Access control

PDP framework indices may contain user/security metadata.

Apply least privilege to:

```text
pdp-evidence-*
pdp-assessment-*
pdp-findings-*
```

The monitoring platform itself remains a Personal Data processing activity and should be assessed accordingly.
